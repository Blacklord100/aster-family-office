# Twelve-quarter source history demonstration

`history-v1` is a separate frozen fictional corpus. It does not replace or modify `mailroom-v1`, and the original mailroom demo remains the default. Select **Connections → Folders → Portfolio history** when starting a new demonstration. The dataset identity is pinned in that run's encrypted workspace. Supported facts go through the normal local extraction, source validation and demo review path.

The corpus contains 100 emails across three fictional families and nine mailbox routes: 97 unique originals, three byte-identical forwarded receipts, 64 PDF attachments and 111 expected extracted facts per receipt. Six funds have twelve quarterly observations from September 2023 through June 2026. Families also receive late reports, corrected valuations, cash notices, bank confirmations, acquisition certificates, incomplete notices and administrative mail. One consolidation names all three families; publication and source release still follow family authorization.

The original MIME files retain their attachments. Only `catalog.json` and `fixtures/emails/*.eml` are copied into the runtime image, and only the emails enter Demo mails. **The worker/processor must never receive `gold.json`, `expected-history.json`, the scoring scripts or the manifest's expected answers.** Standalone attachment copies are for fixture inspection and must not also be ingested.

## Expected financial behavior

- Reported NAV is visible independently of performance availability. Older reports keep their economic dates, including late arrivals.
- Three revised manager reports differ from the previously reported amount. Their corrections require explicit human review; source order must not silently choose a replacement.
- Calls and distributions create linked obligation drafts. Their copies and repeated bank-statement notice amounts do not create additional economic obligations.
- Missing amounts or dates remain unknown. Bank confirmations never settle cash automatically. Explicit transaction preparation, account/FX/classification review and settlement are separate actions.
- Acquisition certificates are retained as sources. They do not establish sourced lifecycle entries until a person reviews and records them.
- The suggested manual cash scenario starts at 500,000.00 and records a 40,000.25 contribution and a 12,500.10 distribution in the family's native currency. It reaches 472,499.85 only after both settlements. Source-supported book cost, distribution treatment, restrictions and FX still need review. No period is claimed reconciled, and no cash-flow-complete investment return is asserted.
- Three administrative emails have no expected facts. Six lifecycle statements are expected as news under the current extraction contract; the dedicated lifecycle command records legal opening dates separately.

Gold records extraction expectations per receipt, including duplicated receipts. `expected-history.json` describes the reviewed end state and explicitly distinguishes actions that must still be performed. Neither file is a model training or prompt input. The answers were authored before inference, but have not been independently human-adjudicated.

## Reproduce and qualify

The generator refuses to overwrite an existing corpus. It uses ReportLab and fixed timestamps/MIME boundaries; no model or processor is imported.

```sh
PYTHONPATH=/path/to/pdf-qa /path/to/python benchmark/history-v1/build_corpus.py --output /new/repro-directory
python3 -m unittest discover -s benchmark/history-v1 -p 'test_*.py'
python3 benchmark/history-v1/verify.py
```

Read the PDF skill before generating a new PDF dataset. Compare every generated byte with the frozen copy. The initial reproducibility check compared 168 generated files with no differences. All 64 PDFs are single-page documents; representative NAV, correction, bank, acquisition and consolidation pages were rendered and inspected. All 100 MIME sources were decoded by the unchanged application processor with no expected source-anchor failures and no model calls.

Use the processor's installed interpreter to record the actual source pages outside the application repository:

```sh
/path/to/processor/python benchmark/history-v1/verify.py --decode /private/new-decoded-directory
```

The source decoder launches its normal bounded PDF subprocess. A fresh output directory is required. The registry includes original content identities, decoded-file hashes and decoder hashes; scoring refuses changed source pages or gold metadata.

After starting a **new** synthetic history demo, export its actual persisted results read-only. This command rejects ordinary workspaces and datasets other than history-v1. It uses the operator's existing private database environment; do not include credentials in arguments or output.

```sh
node --conditions=react-server --import tsx --env-file=.env.local benchmark/history-v1/export-results.ts DEMO_ORGANIZATION_UUID /private/new-export.json
/path/to/processor/python benchmark/history-v1/verify.py --exports /private/new-export.json --decoded /private/new-decoded-directory --output /private/new-score.json
```

Scoring checks all six fact fields, exact decimal amounts and contiguous evidence quotes on the authored source page. Missing, failed and unprocessed jobs stay in the denominator; duplicate jobs for one immutable source are rejected rather than silently selecting a favorable result. Scores are per receipt and distinguish the 97 unique-source processing count. An incomplete run is not a final accuracy result. No model accuracy claim is made by the static fixture checks.

For an offline installation, both shipped datasets work without an email provider. Optional corpus overrides are `ASTER_DEMO_CORPUS_ROOT` for mailroom-v1 and `ASTER_DEMO_HISTORY_CORPUS_ROOT` for history-v1. Both remain inside the existing enabled-demo and approved-intake-root controls.
